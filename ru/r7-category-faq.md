## 📌 Обзор проекта и ТЗ

### Описание проблемы

На сайте [Р7 центр поддержки](https://support.r7-office.ru/) раздел частых вопросов ранее функционировал как статичный шаблон отдельной страницы (`template-faq.php`). Вопросы и ответы вносились контент-менеджерами вручную через repeater-поля ACF. Это создавало проблемы с масштабированием:
1. Невозможность распределять вопросы по рубрикам таксономии WordPress.
2. Дублирование контента между обычными базами знаний и разделом FAQ.
3. Отсутствие удобного шеринга — не было возможности скопировать прямую ссылку на конкретный вопрос аккордеона.
4. Медленный рендеринг при увеличении числа вопросов из-за повторных вызовов тяжелых фильтров `the_content` для каждого элемента.

### Техническое задание (ТЗ)

* **Модульность шаблона:** Разработать новый шаблон `category-faq` в рамках подсистемы `category-templates`, позволяющий превратить архив любой рубрики сайта в динамический FAQ-аккордеон.
* **Источник данных:** Вопросы формируются из заголовков постов рубрики, а ответы — из их содержимого (`post_content`), исключая необходимость дублирования данных в ACF.
* **Якорная навигация:** Реализовать систему глубоких ссылок (`#slug`) с автоматическим раскрытием нужного вопроса при переходе и кнопкой копирования прямых URL в буфер обмена (`[data-copy-anchor]`).
* **Оптимизация производительности:** Исключить N+1 проблемы при генерации ответов, внедрить кэширование обработанного HTML-контента и устранить микро-задержки (Layout Thrashing) при кликах по аккордеонам.
* **REST API Подгрузка:** Разработать эндпоинт для фоновой асинхронной загрузки ответов без перезагрузки страницы.

## 💡 Пример наиболее сложной задачи: Task 08 — Вынести служебный запрос в REST-эндпоинт

::: details 📋 Посмотреть полностью ТЗ и реализацию задачи № 08 (REST API Endpoint)

### Исходная проблема

Служебный запрос поиска якоря живет прямо на адресе рубрики в `index.php` и перехватывает обычный GET-запрос. Проблемы две: его может незаметно отключить любой плагин, вмешивающийся в выбор шаблона, и его ответ может закешироваться CDN и потом прилететь посетителю вместо страницы.

### Постановка задачи

> **Цель:** Убрать служебный запрос из `index.php`, где он перехватывает GET и может быть закеширован CDN или отключён плагином. Перенести логику поиска якоря в отдельный REST-эндпоинт WordPress — явный, изолированный и по умолчанию защищённый от кеширования.

### Реализация REST-маршрута (`inc/faq-anchor-endpoint.php`)

```php
<?php
if ( ! defined( 'ABSPATH' ) ) {
    exit;
}

add_action(
    'rest_api_init',
    static function () {
        register_rest_route(
            'r7/v1',
            '/faq-anchor',
            array(
                'methods'             => WP_REST_Server::READABLE,
                'permission_callback' => '__return_true',
                'callback'            => 'r7_category_faq_locate_anchor',
                'args'                => array(
                    'category' => array(
                        'required'          => true,
                        'sanitize_callback' => 'absint',
                    ),
                    'slug'     => array(
                        'required'          => true,
                        'sanitize_callback' => 'sanitize_title',
                    ),
                ),
            )
        );
    }
);

function r7_category_faq_locate_anchor( WP_REST_Request $request ) {
    $term_id = (int) $request->get_param( 'category' );
    $slug    = (string) $request->get_param( 'slug' );

    $term = get_term( $term_id, 'category' );
    if ( is_wp_error( $term ) || ! ( $term instanceof WP_Term ) ) {
        return new WP_Error( 'r7_faq_bad_category', 'Рубрика не найдена.', array( 'status' => 404 ) );
    }

    $target = get_posts(
        array(
            'name'                   => $slug,
            'post_type'              => 'post',
            'post_status'            => 'publish',
            'cat'                    => $term_id,
            'numberposts'            => 1,
            'update_post_meta_cache' => false,
            'update_post_term_cache' => false,
        )
    );

    if ( empty( $target ) ) {
        return new WP_Error( 'r7_faq_not_found', 'Вопрос не найден.', array( 'status' => 404 ) );
    }

    return rest_ensure_response(
        array( 'faq_page' => r7_category_faq_get_page_for_post( $term_id, $target[0] ) )
    );
}
```

### Обход ограничений Clearfy Pro (Whitelist)

Плагин Clearfy Pro ограничивает REST API для неавторизованных пользователей. Namespace `r7` явно добавляется в белый список:


## ⚡ Технические решения и ключевые сложности

### Сложность 1: Устранение Layout Thrashing (плавный аккордеон на HTML5 `<details>`)

::: warning Проблема
Стандартный элемент `<details>` не поддерживает плавнонимируемое свойство `height: auto` в CSS. Попытки измерять `scrollHeight` в JavaScript во время клика вызывают повторную компоновку документа (Reflow/Layout Thrashing), что приводит к фризам UI на мобильных устройствах.
:::

::: tip 💡 Решение: CSS Grid `grid-template-rows` анимация
Вместо JS-измерения высоты используется современный CSS-трюк с анимацией сетки CSS Grid от `0fr` до `1fr`, выполняемый полностью на GPU без вызова JS-рефлоу:

```css
/* Контейнер ответа внутри <details> */
.faq-accordion__content-wrapper {
    display: grid;
    grid-template-rows: 0fr;
    transition: grid-template-rows 0.25s cubic-bezier(0.4, 0, 0.2, 1);
}

/* Раскрытое состояние */
.faq-accordion[open] .faq-accordion__content-wrapper {
    grid-template-rows: 1fr;
}

/* Внутренний блок с overflow: hidden */
.faq-accordion__content {
    overflow: hidden;
}
```
:::

### Сложность 2: Мгновенное авто-раскрытие вопроса при переходе по якорной ссылке (`#hash`)

::: warning Проблема
Если пользователь переходит по ссылке вида `https://support.r7-office.ru/category/faq/#how-to-setup`, браузер пытается прокрутить страницу до якоря ДО того, как JavaScript успеет раскрыть `<details>`. В результате страница скроллится в некорректную позицию.
:::

::: tip 💡 Решение: Синхронный Micro-script в `head`
Небольшой инлайн-скрипт выполняется до рендеринга тела страницы, моментально находя нужный тег `<details>` по `location.hash` и устанавливая ему атрибут `open`:

```html
<script>
(function(){
    var hash = window.location.hash;
    if (hash && hash.length > 1) {
        var id = hash.substring(1);
        var target = document.getElementById(id);
        if (target && target.tagName === 'DETAILS') {
            target.setAttribute('open', '');
        }
    }
})();
</script>
```
:::
