## <SolarIcon name="pin" /> Обзор проекта и ТЗ

### Описание проблемы

В статьях сайта [Р7 центр поддержки](https://support.r7-office.ru/) и вопросах FAQ подписи к иллюстрациям выводились разрозненно. В одних статьях авторы вручную писали `Рисунок 1. ...`, в других — `Рис. 1: ...`, а в третьих подписи вообще сливались с основным текстом из-за отсутствия явных CSS-стилей. 

При редактировании или удалении одного из изображений в середине статьи авторам приходилось **вручную перенумеровывать все последующие рисунки**.

### Технические требования (ТЗ)

### Сравнение рассмотренных вариантов реализации

Перед выбором итогового решения проводился технический анализ трёх архитектурных способов автоматизации нумерации (`image-captions-proposal.txt`):

| Способ | Механизм | Плюсы | Минусы | Вердикт |
|---|---|---|---|:---:|
| **1. PHP-фильтр на регулярных выражениях** | Хук `the_content`, поиск `<figcaption>` через regex и подстановка номера | • Номер виден поисковикам (SEO)<br>• Работает в статьи и FAQ одинаково | • Хрупкость regex при обновлениях WP<br>• Нагрузка на CPU при парсинге текста на каждый запрос<br>• Риск дублирования ручного текста | ❌ Отклонён |
| **2. PHP-фильтр с DOM-парсингом** | Хук `the_content` + `DOMDocument` / `Dom\HTMLDocument` (PHP 8.4+) | • Надежная работа с HTML-деревом<br>• Номер прошит в исходном коде | • На PHP <=8.3 сложная работа с UTF-8/кириллицей<br>• Зависимость от версии PHP на сервере<br>• Медленнее регулярок | ❌ Отклонён |
| **3. CSS-счётчики (CSS Counters)** | `counter-reset`, `counter-increment` и псевдоэлементы `::before` | • **0 KB JS, 0 ms CPU execution**<br>• 0 изменений в БД и PHP<br>• Простая поддержка и сбрасываемый контекст | • Номер существует только в визуальном рендере браузера | ✅ **Выбран** |

::: details <SolarIcon name="clipboard" /> Посмотреть подробно аргументацию и сравнение из отчёта `image-captions-proposal.txt`

#### Способ 1 — PHP-фильтр с регулярными выражениями
WordPress при вставке изображения с подписью генерирует разметку с тегом `<figcaption class="wp-caption-text">`. Фильтр на хуке `the_content` проходит регулярным выражением по HTML и подставляет «Рис. N:».
* **Плюсы:** Номер прошит в HTML и виден поисковикам.
* **Минусы:** Лишний атрибут или пробел в теге может сломать совпадение после обновления WordPress; при каждом запросе PHP заново парсит весь контент статьи; нужно обрабатывать ручной ввод «Рис. 1:» во избежание дублирования.

#### Способ 2 — PHP-фильтр с DOM-парсингом
Тот же хук `the_content`, но вместо регулярки HTML загружается в PHP-объект парсера (на PHP >= 8.4 — `Dom\HTMLDocument`, на PHP <= 8.3 — `DOMDocument`).
* **Плюсы:** Более надёжный разбор структуры тегов.
* **Минусы:** На PHP <= 8.3 классический `DOMDocument` требует костылей с кодировкой (`mb_convert_encoding`) и некорректно парсит HTML5; медленнее регулярок; требует проверки версии PHP на сервере.

#### Способ 3 — CSS-счётчики (CSS Counters) — Выбранный вариант
Браузер считает элементы на странице встроенными средствами CSS через `counter-reset` / `counter-increment`. Псевдоэлемент `::before` подставляет «Рисунок N:» автоматически при отрисовке.
* **Плюсы:** Ноль нагрузки на сервер; не трогает PHP, шаблоны и базу данных; простая смена формата подписи («Рис.» → «Fig.»); работает для новых и существующих статей без доработок.
* **Минусы:** Номер существует только в визуальном рендере браузера.

## <SolarIcon name="lightbulb" /> Пример наиболее сложной задачи: Task 03-1 — Реализация автонумерации на CSS Counters

::: details <SolarIcon name="clipboard" /> Посмотреть полностью ТЗ и реализацию задачи № 03-1

### Техническое решение подписей на чистом CSS3

Счётчики CSS (`CSS Counters`) позволяют реализовывать нумерацию элементов в DOM без единой строки JS-кода. 

#### Исходный код реализации в `themes/r7/assets/stylesheets/common.css`:

```css
/* ===== 1. Инициализация и сброс счетчика рисунков ===== */
.wysiwyg-result,
.faq-item__answer {
    counter-reset: r7-figure-counter; /* Сбрасываем счетчик в начале каждой статьи/вопроса */
}

/* ===== 2. Увеличение счетчика для каждой подписи ===== */
.wysiwyg-result figure,
.wysiwyg-result .wp-caption,
.faq-item__answer figure,
.faq-item__answer .wp-caption {
    counter-increment: r7-figure-counter;
}

/* ===== 3. Стилизация и вывод префикса "Рисунок N:" ===== */
.wysiwyg-result figcaption,
.wysiwyg-result .wp-caption-text,
.faq-item__answer figcaption,
.faq-item__answer .wp-caption-text {
    margin-top: calc(12 / 16 * 1rem);
    font-size: calc(14 / 16 * 1rem);
    line-height: 1.4;
    color: var(--ne-lght-600, #8b929b);
    text-align: center;
}

/* Автоматическая подстановка префикса "Рисунок N: " */
.wysiwyg-result figcaption::before,
.wysiwyg-result .wp-caption-text::before,
.faq-item__answer figcaption::before,
.faq-item__answer .wp-caption-text::before {
    content: "Рисунок " counter(r7-figure-counter) ": "; /* [!code ++] */
    font-weight: 600;
    color: var(--ne-lght-800, #4b5563);
}
```

## <SolarIcon name="bolt" /> Технические решения и ключевые сложности

### Сложность 1: Предотвращение ложной нумерации пустых элементов

::: warning Проблема
Если в редакторе случайным образом остался пустой тег `<figcaption></figcaption>`, CSS Counter всё равно увеличивал значение счётчика, сбивая Нумерацию следующих настоящих иллюстраций.
:::

::: tip <SolarIcon name="lightbulb" /> Решение: Селекторы `:not(:empty)`
Псевдоэлемент префикса применяется только в том случае, если контейнер подписи содержит реальный текст:

```css
/* Нумеруем только те подписи, где есть текст */
.wysiwyg-result figcaption:not(:empty)::before,
.faq-item__answer figcaption:not(:empty)::before {
    content: "Рисунок " counter(r7-figure-counter) ": ";
}
```
:::

### Сложность 2: Ручной ввод префикса автором статьи

::: warning Проблема
Если контент-менеджер по привычке уже написал в админке `Рисунок 1: Главное окно`, в итоге выводилось дублирование: `Рисунок 1: Рисунок 1: Главное окно`.
:::

::: tip <SolarIcon name="lightbulb" /> Решение: Рекомендация для авторов
Было подготовлено руководство по контент-стандартам, предписывающее авторам вводить в поле подписи только чистый описательный текст. Префикс добавляется автоматически на стороне фронтенда.
:::
