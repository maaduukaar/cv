## 📌 Обзор проекта и ТЗ

### Описание проблемы

В статьях сайта [Р7 центр поддержки](https://support.r7-office.ru/) и вопросах FAQ подписи к иллюстрациям выводились разрозненно. В одних статьях авторы вручную писали `Рисунок 1. ...`, в других — `Рис. 1: ...`, а в третьих подписи вообще сливались с основным текстом из-за отсутствия явных CSS-стилей. 

При редактировании или удалении одного из изображений в середине статьи авторам приходилось **вручную перенумеровывать все последующие рисунки**.

### Технические требования (ТЗ)

1. **Единый визуальный стандарт:** Все подписи (`<figcaption>` и `.wp-caption-text`) должны иметь строго фиксированный размер шрифта (14px), серый цвет текста (`#8b929b`), выравнивание и верхний отступ (12px).
2. **Автоматическая нумерация (CSS Counters):** Реализовать автоматическое добавление префикса **«Рисунок 1: »**, **«Рисунок 2: »** на чистом CSS без вмешательства JavaScript и без изменения базы данных WordPress.
3. **Изоляция счётчиков:** Нумерация рисунков должна начинаться заново в каждой новой статье `.wysiwyg-result` и в каждом отдельном раскрывающемся вопросе FAQ `.faq-item__answer`.

## 💡 Пример наиболее сложной задачи: Task 03-1 — Реализация автонумерации на CSS Counters

::: details 📋 Посмотреть полностью ТЗ и реализацию задачи № 03-1

### Техническое решение подписей на чистом CSS3

Счётчики CSS (`CSS Counters`) позволяют реализовывать нумерацию элементов в DOM без единой строки JS-кода. 

#### Исходный код реализации в `themes/r7/assets/stylesheets/common.css`:

```css
/* ===== 1. Инициализация и сброс счетчика рисунков ===== */
.wysiwyg-result,
.faq-item__answer {
    counter-reset: r7-figure-counter; /* Сбрасываем счетчик в начале каждой статьи/вопроса */
}

/* ===== 2. Увеличение счетчика для каждой подписи ===== */
.wysiwyg-result figure,
.wysiwyg-result .wp-caption,
.faq-item__answer figure,
.faq-item__answer .wp-caption {
    counter-increment: r7-figure-counter;
}

/* ===== 3. Стилизация и вывод префикса "Рисунок N:" ===== */
.wysiwyg-result figcaption,
.wysiwyg-result .wp-caption-text,
.faq-item__answer figcaption,
.faq-item__answer .wp-caption-text {
    margin-top: calc(12 / 16 * 1rem);
    font-size: calc(14 / 16 * 1rem);
    line-height: 1.4;
    color: var(--ne-lght-600, #8b929b);
    text-align: center;
}

/* Автоматическая подстановка префикса "Рисунок N: " */
.wysiwyg-result figcaption::before,
.wysiwyg-result .wp-caption-text::before,
.faq-item__answer figcaption::before,
.faq-item__answer .wp-caption-text::before {
    content: "Рисунок " counter(r7-figure-counter) ": "; /* [!code ++] */
    font-weight: 600;
    color: var(--ne-lght-800, #4b5563);
}
```

## ⚡ Технические решения и ключевые сложности

### Сложность 1: Предотвращение ложной нумерации пустых элементов

::: warning Проблема
Если в редакторе случайным образом остался пустой тег `<figcaption></figcaption>`, CSS Counter всё равно увеличивал значение счётчика, сбивая Нумерацию следующих настоящих иллюстраций.
:::

::: tip 💡 Решение: Селекторы `:not(:empty)`
Псевдоэлемент префикса применяется только в том случае, если контейнер подписи содержит реальный текст:

```css
/* Нумеруем только те подписи, где есть текст */
.wysiwyg-result figcaption:not(:empty)::before,
.faq-item__answer figcaption:not(:empty)::before {
    content: "Рисунок " counter(r7-figure-counter) ": ";
}
```
:::

### Сложность 2: Ручной ввод префикса автором статьи

::: warning Проблема
Если контент-менеджер по привычке уже написал в админке `Рисунок 1: Главное окно`, в итоге выводилось дублирование: `Рисунок 1: Рисунок 1: Главное окно`.
:::

::: tip 💡 Решение: Рекомендация для авторов
Было подготовлено руководство по контент-стандартам, предписывающее авторам вводить в поле подписи только чистый описательный текст. Префикс добавляется автоматически на стороне фронтенда.
:::
