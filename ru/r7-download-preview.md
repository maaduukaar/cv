## <SolarIcon name="pin" /> Обзор проекта и ТЗ

В рамках расширения экосистемы **Р7-Офис** и запуска программы раннего доступа **«Время первых»** потребовалось спроектировать и реализовать посадочную страницу для дистрибуции предварительных, альфа- и бета-версий продуктов компании до их официального релиза в основном каталоге.

### Исходная проблема и контекст

1. **Многообразие платформ и сборок:** 8 ключевых продуктов компании (Редактор документов, Сервер Р7-Ассистент, Органайзер ПРО, Графика, Корпоративный сервер, Сервер документов, Почтовый сервер, Файл-экспресс) поставляются под 14 различных операционных систем и архитектур (Windows, macOS, RedOS, CentOS, Astra Linux, Ubuntu, ROSA, Alt Linux, SUSE, iOS, Android, Аврора, Docker-образы и патчи). Пользователю требовался удобный, интуитивный выбор своей ОС с мгновенным получением нужного дистрибутива, размера файла и контрольной суммы MD5.
2. **Изоляция в дочерней теме:** Основная тема сайта `themes/r7` находится в непрерывной поддержке. Все новые шаблоны, кастомные скрипты, стили и SVG-спрайты необходимо было изолировать в дочерней теме `themes/r7-child`, исключив влияние на основной сайт.
3. **Безопасность и делегирование контента (RBAC):** Обновлением ссылок на свежие сборки и контрольных сумм занимаются назначенные контент-менеджеры. При этом менеджеры **не должны иметь доступа к чужим страницам сайта**, но обязаны беспрепятственно редактировать страницу лендинга, созданную другим автором, включая сохранение сложных структур JSON через ACF без вырезания тегов и экранирования.
4. **Юридическое соответствие:** Загрузка предварительных версий требует обязательного подтверждения согласия пользователя с лицензионными условиями использования предварительного ПО перед началом скачивания.

### Техническое задание (ТЗ)

- **Шаблон страницы:** Разработать кастомный PHP-шаблон `template-download-preview.php` с Hero-баннером (слайдер 7 изображений продуктов), сеткой карточек продуктов, табами ОС и всплывающим модальным окном соглашения.
- **Оптимизация ассетов:** CSS и JS страницы превью подключаются строго по условию `is_page_template()`, не создавая оверхеда на других страницах базы знаний.
- **Must-Use плагин RBAC:** Создать изолированную роль менеджера превью-версий (`preview_landing_editor`) с гранулярным доступом только к целевым ID лендингов через хуки ядра `map_meta_cap`, `acf/allow_unfiltered_html` и `admin_menu`.
- **Интеграция с родительским шаблоном:** Добавить опциональный управляемый баннер альфа-версий в стандартный шаблон скачивания (`template-download.php`) через ACF.

## <SolarIcon name="lightbulb" /> Пример наиболее сложной задачи

### Разработка Must-Use плагина гранулярного RBAC (`preview-landing-role-manager.php`)

Одной из наиболее нетривиальных инженерных задач проекта стало создание изолированной роли для контент-менеджеров с соблюдением принципа наименьших привилегий (Principle of Least Privilege).

```text
Задача: Менеджер должен редактировать страницу ID 55188, созданную Администратором,
        сохранять в ACF сложные JSON-структуры со спецсимволами и кавычками,
        но НЕ иметь доступа к 500+ другим статьям и системным настройкам WordPress.
```

::: details <SolarIcon name="code" /> Посмотреть реализацию ключевых хуков mu-плагина

```php:line-numbers [mu-plugins/preview-landing-role-manager.php]
<?php
/**
 * Plugin Name: Preview Landing Role Manager
 * Description: Создаёт роль менеджера лендинга превью-версий и ограничивает доступ целевыми страницами.
 * Version: 1.1.0
 */

if (!defined('ABSPATH')) {
    exit;
}

define('TARGET_LANDING_IDS', array(55188, 55197));
define('CUSTOM_ROLE_SLUG', 'preview_landing_editor');
define('CUSTOM_ROLE_NAME', 'Менеджер лендинга превью-версий');

/**
 * 1. Идемпотентная регистрация роли на init
 */
add_action('init', function () {
    if (null !== get_role(CUSTOM_ROLE_SLUG)) {
        return;
    }

    add_role(
        CUSTOM_ROLE_SLUG,
        CUSTOM_ROLE_NAME,
        array(
            'read'                 => true,
            'upload_files'         => true,
            'edit_pages'           => true,
            'edit_published_pages' => true,
            'publish_pages'        => true,
        )
    );
});

/**
 * 2. Гранулярное переопределение прав через map_meta_cap
 * Обход блокировки Classic Editor для чужих страниц без выдачи глобального edit_others_pages
 */
add_filter('map_meta_cap', function ($caps, $cap, $user_id, $args) {
    static $role_cache = array();
    if (!isset($role_cache[$user_id])) {
        $user = get_userdata($user_id);
        $role_cache[$user_id] = $user && in_array(CUSTOM_ROLE_SLUG, (array) $user->roles, true);
    }
    if (!$role_cache[$user_id]) {
        return $caps;
    }

    $post_id = isset($args[0]) ? absint($args[0]) : 0;

    // Для целевых лендингов edit_post сводим к базовому edit_pages, которое есть у роли // [!code ++]
    if (in_array($post_id, TARGET_LANDING_IDS, true) && in_array($cap, array('edit_post', 'edit_page'), true)) { // [!code ++]
        return array('edit_pages'); // [!code ++]
    } // [!code ++]

    // Удаление страниц запрещено безусловно
    if (in_array($cap, array('delete_post', 'delete_page', 'delete_others_pages', 'delete_published_pages'), true)) {
        return array('do_not_allow');
    }

    // Блокируем доступ к любым другим страницам
    if (in_array($cap, array('edit_others_pages', 'edit_others_posts'), true) || in_array('edit_others_pages', $caps, true)) {
        if ($post_id && in_array($post_id, TARGET_LANDING_IDS, true)) {
            return array('edit_pages');
        }
        return array('do_not_allow'); // [!code highlight]
    }

    return $caps;
}, 10, 4);

/**
 * 3. Разрешение фильтрации ACF для сырых JSON-структур
 */
add_filter('acf/allow_unfiltered_html', function ($allowed) {
    $user = wp_get_current_user();
    if ($user && in_array(CUSTOM_ROLE_SLUG, (array) $user->roles, true)) {
        return true; // Предотвращает вырезание кавычек и ссылок в JSON // [!code ++]
    }
    return $allowed;
});

/**
 * 4. Очистка админ-меню от посторонних разделов
 */
add_action('admin_menu', function () {
    $user = wp_get_current_user();
    if (!$user || !in_array(CUSTOM_ROLE_SLUG, (array) $user->roles, true)) {
        return;
    }

    // Оставляем только Страницы, Медиафайлы и Профиль
    remove_menu_page('edit.php');                   // Записи
    remove_menu_page('edit-comments.php');          // Комментарии
    remove_menu_page('tools.php');                  // Инструменты
    remove_menu_page('options-general.php');        // Настройки
    remove_menu_page('wpcf7');                      // Contact Form 7
}, 999);
```

## <SolarIcon name="bolt" /> Технические решения и ключевые сложности

### 1. Архитектура темы: Fatal Error при наследовании шаблонов <Badge type="danger" text="Critical Bug" />

::: warning Проблема
После первичной активации дочерней темы `r7-child` сайт падал с критической ошибкой `Fatal Error: require_once(): Failed opening required .../themes/r7-child/inc/category-templates/loader.php`.

**Причина:** В ядре родительской темы `r7/functions.php` подключение внутренних модулей производилось через `get_stylesheet_directory()`, которая для дочерней темы возвращает путь к папке дочерней темы, где ядровые лоадеры отсутствуют.
:::

::: tip <SolarIcon name="lightbulb" /> Решение: Двухуровневое устранение проблемы
1. **Быстрое восстановление (Proxy Loader):** В дочерней теме создан файл-прокси `themes/r7-child/inc/category-templates/loader.php`, безопасно делегирующий вызов на родительскую директорию через `get_template_directory()`.
2. **Системный патч:** В родительской теме `r7/functions.php` заменены вызовы `get_stylesheet_directory()` на `get_template_directory()` для всех системных модулей, не подлежащих обязательному переопределению в дочерних темах.
:::

### 2. Производительность: Кеширование данных и серверный отклик <Badge type="tip" text="wp_cache" />

::: warning Проблема
Массив дистрибутивов и метаданных для 8 линеек продуктов и 14 ОС занимает **82 KB** PHP-структур. При стандартной реализации функция получения данных выполняла вызовы `wp_upload_dir()`, дисковые проверки `file_exists()` и парсинг файла при каждом открытии страницы любым посетителем.
:::

::: tip <SolarIcon name="rocket" /> Решение: In-Memory Object Caching со сбросом при сохранении
Внедрено двухуровневое кеширование через WordPress Object Cache API (`wp_cache_get` / `wp_cache_set` в группе `r7_preview`):

```php
function r7_get_preview_products_data() {
    $cached = wp_cache_get('preview_products_data', 'r7_preview');
    if (false !== $cached) {
        return $cached; // Мгновенная отдача из памяти // [!code ++]
    }

    // Чтение и валидация файла...
    if (is_array($data)) {
        wp_cache_set('preview_products_data', $data, 'r7_preview');
        return $data;
    }
    return [];
}

// Автоматический сброс кеша при обновлении данных контент-менеджером
add_action('acf/save_post', function ($post_id) {
    wp_cache_delete('preview_products_data', 'r7_preview'); // [!code highlight]
}, 20);
```
:::

### 3. Интерактивный UX: Табы 14 ОС и модальное окно условий <Badge type="info" text="JavaScript ES6" />

::: warning Проблема
Требовалось поддержать 14 ОС с уникальными иконками, лейблами архитектур (`WIN 64 ZIP`, `RPM`, `DEB`, `Docker`), размерами и MD5-хэшами. При этом скачивание должно обязательно блокироваться до принятия лицензионного соглашения, а копирование хэша должно быть мгновенным и наглядным на мобильных и десктопных устройствах.
:::

::: tip <SolarIcon name="palette" /> Решение: SVG-спрайты, Clipboard API и модальный контроллер
- **Векторный спрайт:** Сформирован единый кешируемый SVG-спрайт `preview-sprite.svg` с символами операционных систем, исключивший лишние HTTP-запросы.
- **Интерактивные табы:** Переключение ОС внутри карточек продуктов работает через CSS Grid и мгновенные data-атрибуты без перезагрузки страницы.
- **Clipboard Feedback:** Кнопки копирования MD5 обращаются к `navigator.clipboard.writeText()` и отображают тултип «Скопировано!» с временной анимацией.
- **Модальный перехват:** Любой клик по кнопке скачивания перехватывается, ссылка запоминается в контексте модального окна, а кнопка согласия становится активной только после установки чекбокса.
:::
