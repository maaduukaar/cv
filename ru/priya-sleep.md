## <SolarIcon name="pin" /> Обзор проекта и ТЗ

**Priya Sleep (Прия Спит)** — специализированное мобильное веб-приложение формата Telegram Mini App в связке с Telegram-ботом, спроектированное для молодых родителей и консультантов по детскому сну. Приложение автоматизирует трекинг фаз сна и бодрствования ребенка, предотвращает «перегул» и дает наглядную картину режима дня.

  <img src="/ru/images/priya-sleep/whole-day-stat.webp" alt="Суточная статистика сна и бодрствования в Priya Sleep">
  <figcaption>Суточный таймлайн с разделением на дневные и ночные периоды, расчетом времени бодрствования (ВБ) и процентом нормы сна</figcaption>
</figure>

### Проблематика существующих решений

1. **Неудобство мобильных приложений из App Store / Google Play:** Большинство трекеров перегружены баннерной рекламой, требуют платных подписок, долго запускаются при открытии и не позволяют быстро передать статистику второму родителю или консультанту.
2. **Контекст усталости родителей:** Фиксация сна часто происходит в темноте, одной рукой, в состоянии хронического недосыпа. Любые лишние клики, сложные селекторы дат или сбои интерфейса приводят к ошибкам ввода.
3. **Нестабильное соединение (Slow 3G / Offline):** При укладывании ребенка за городом или в комнатах с плохим приемом сотовой сети стандартные веб-приложения теряют несохраненные данные или создают дубликаты записей при повторных кликах.
4. **Необходимость проактивных напоминаний:** Родителю важно не просто записывать факты, а получать **своевременные предупреждения** о приближении критического порога времени бодрствования (ВБ), чтобы вовремя начать ритуал укладывания.

### Техническое задание и цели разработки

- **Telegram-First экосистема:** Работа напрямую внутри мессенджера без установки сторонних приложений через нативный `window.Telegram.WebApp`.
- **UX фиксации в 1 тап:** Единая крупная кнопка переключения состояний («Уснула» 🌙 / «Проснулась» ☀️) с автоподстановкой времени и жестовым time picker.
- **Интеллектуальная аналитика режима:** Автоматический расчет продолжительности сна, периодов бодрствования, разделение суток на Дневной (08:00–20:00) и Ночной (20:00–08:00) периоды, расчет суммарного сна и процента выполнения возрастной нормы.
- **Telegram Bot (Awake Alerts):** Асинхронный Python-сервис на базе `aiogram`, непрерывно отслеживающий текущее состояние каждого пользователя и присылающий персонализированные пуш-уведомления с именем ребенка перед наступлением перегула с учетом «тихих часов».
- **Консультационный режим (Admin Connect):** Возможность для сертифицированного сомнолога или второго родителя временно подключиться к аккаунту подопечного через бота по команде `/userId` для анализа и корректировки дневника.

### Ключевые компоненты UI/UX

1. **Пастельная успокаивающая палитра:**
   - Фон: мягкий диагональный градиент `#F5F0FF` → `#FFF8F5` (лилово-кремовый).
   - Лиловый акцент (`#C9B1FF` / `#A78BFA`) — фаза сна, заголовки, расслабление.
   - Розовый акцент (`#FFB5C5` / `#F9A8D4`) — фаза пробуждения и бодрствования.
   - Шалфейный зеленый (`#B5D4C1`) — показатели нормы и успешные таймлайны.
2. **Glassmorphism-карточки:** Полупрозрачные подложки `rgba(255, 255, 255, 0.7)` с `backdrop-filter: blur(12px)`, создающие ощущение легкости.
3. **Интерактивный Wheel Time Picker:**
   - Отображает текущее время по умолчанию.
   - Позволяет скорректировать время на ±5, ±15 минут или прокрутить барабан времени.
   - **Wheel Picker Interaction Guard:** Специальный защитный таймер блокирует случайные клики по кнопке фиксации в момент инерционной прокрутки колеса времени.
4. **Жестовое управление (Mobile Gestures):**
   - **Свайп вправо по карточке:** Открывает модальное окно редактирования времени начала и конца записи с каскадным пересчетом соседних интервалов.
   - **Свайп влево:** Мгновенное безопасное удаление ошибочной записи с анимацией схлопывания.
5. **Личная комната (User Custom UI):** Архитектура изоляции стилей, позволяющая настраивать виджеты, акценты и шрифты индивидуально для каждого профиля с сохранением только дельты переопределений в JSON.

## <SolarIcon name="lightbulb" /> Разбор сложной инженерной задачи: Устранение Race Condition при медленной сети

В процессе полевого тестирования на мобильных устройствах с нестабильным 3G-соединением был выявлен критический баг: при нажатии кнопки «Проснулась» иногда создавались **две параллельные сессии сна** или сон обрывался без создания бодрствования.

<figure>
  <img src="/ru/images/priya-sleep/moon-stat.webp" alt="Месячная аналитика сна в Priya Sleep">
  <figcaption>Точный расчет регулярности и трендов сна требует 100% целостности цепочки записей без разрывов и наложений</figcaption>
</figure>

### Анализ первопричины сбоя (Root Cause)

Исходная реализация содержала **разрыв состояния (State Gap)** между завершением предыдущей сессии и началом следующей:

```javascript
// ❌ ИСХОДНЫЙ ПРОБЛЕМНЫЙ КОД (Race Condition)
async function endSleep(time) {
    // 1. Завершаем активный сон
    const duration = await finishActiveRecord(time);
    // ⚠️ Внутри finishActiveRecord происходило: state.activeRecord = null;
    // ⚠️ Браузер ждет ответа от медленного сервера (1-3 секунды).
    
    // 2. Если в этот момент пользователь нажимает кнопку повторно или срабатывает авто-таймер:
    // UI видит activeRecord === null и считает, что ребенок бодрствует, инициируя ошибочный старт!
    
    await startAwake(time);
}
```

### Архитектурное решение: Атомарный переход состояний (Atomic State Transition)

Была разработана модель атомарного переключения с мгновенным оптимистичным обновлением (Optimistic UI):

1. **State Locking:** Кнопка и действия блокируются на время выполнения операции.
2. **Мгновенная подмена `state.activeRecord`:** До первого сетевого `await` активная сессия подменяется на временный объект бодрствования с флагом `id: 'temp'`.
3. **Единый пакетный запрос или согласованная последовательность:**

```javascript:line-numbers [app/js/app.js]
async function endSleep(time) {
    const currentRecord = state.activeRecord;
    
    if (!currentRecord || currentRecord.type !== 'sleep') {
        return;
    }

    // 1. Защита от повторных нажатий (Locking Guard) // [!code ++]
    if (state.isTransitioning) return; // [!code ++]
    state.isTransitioning = true; // [!code ++]

    const sleepDuration = calculateDuration(currentRecord.startTime, time);
    
    const awakeRecord = {
        type: 'awake',
        startTime: time,
        date: getCurrentDateString(),
        createdAt: new Date().toISOString()
    };
    
    // 2. АТОМАРНО: устанавливаем optimistic state ДО любых асинхронных вызовов // [!code ++]
    state.activeRecord = { ...awakeRecord, id: 'temp-active' }; // [!code ++]
    updateUI(); // Мгновенный отклик интерфейса для пользователя // [!code ++]
    
    try {
        // 3. Сохраняем завершение сна на сервере
        await Storage.updateRecord(currentRecord.id, {
            endTime: time,
            duration: sleepDuration,
            isCompleted: true
        });
        
        // 4. Создаем запись бодрствования и получаем реальный постоянный ID
        const savedAwake = await Storage.addRecord(awakeRecord);
        
        // 5. Обновляем ID временного объекта без сброса в null
        if (state.activeRecord && state.activeRecord.id === 'temp-active') { // [!code highlight]
            state.activeRecord = savedAwake; // [!code highlight]
        } // [!code highlight]
        
        showToast('Прия проснулась ☀️');
    } catch (error) {
        // Откат состояния при сбое сети
        state.activeRecord = currentRecord;
        showToast('Ошибка сети. Попробуйте еще раз', 'danger');
    } finally {
        state.isTransitioning = false; // [!code ++]
        updateUI();
    }
}
```

## <SolarIcon name="bolt" /> Ключевые технические решения и вызовы

### 1. Фоновая синхронизация и актуализация таймеров (Visibility Refresh)

::: warning Проблема
Telegram Mini App часто сворачивается пользователем в фоновый режим. Встроенные таймеры `setInterval` в фоновом табе браузера замедляются или останавливаются операционной системой (throttling), из-за чего при разворачивании приложения таймер показывал устаревшее время бодрствования.
:::

::: tip <SolarIcon name="lightbulb" /> Решение: Синхронизация по системным событиям фокуса
Внедрен слушатель событий `visibilitychange` и `focus`, выполняющий мгновенный пересчет дельт времени по системным часам устройства и сверку с сервером:

```javascript
document.addEventListener('visibilitychange', () => {
    if (document.visibilityState === 'visible') {
        // Мгновенно синхронизируем таймеры по реальному Date.now()
        recalculateActiveTimers();
        // Асинхронно сверяем данные с сервером
        Storage.syncLatest();
    }
});
```
:::

### 2. Фоновый сервис Awake Alerts на Python и aiogram 3.x

::: info <SolarIcon name="speaker" /> Архитектура системы оповещений
Бот функционирует в непрерывном асинхронном цикле и контролирует пороги бодрствования без использования тяжелых внешних очередей:

1. Каждые 60 секунд фоновый таск считывает активные сессии из `data/users/*.json`.
2. Если текущее время бодрствования достигает `awakeThresholdMinutes` (например, 90 минут), бот проверяет «тихие часы» (`quietHours`: 22:00–07:00).
3. При наступлении триггера бот отправляет сообщение:
   > 🔔 **Время бодрствования:** Прия бодрствует уже **1 ч 30 мин** (норма для 7 месяцев: 1 ч 15 мин – 1 ч 45 мин). Пора готовиться ко сну!
4. Повторные напоминания отправляются с интервалом `reminderIntervalMinutes` во избежание спама.
:::

### 3. Режим консультанта (Admin Connect) без нарушения безопасности

::: warning Проблема
Консультанту по детскому сну необходимо просматривать и корректировать дневник сна подопечного, не требуя от родителя логинов и паролей и не объединяя базы данных разных семей.
:::

::: tip <SolarIcon name="shield" /> Решение: Сессионный прокси-доступ через бота
1. Администратор отправляет боту команду `/{targetUserId}`.
2. Бот проверяет белый список в `data/config.json` и сохраняет активную связку в `data/admin-sessions.json`.
3. При открытии Mini App бэкенд отдает интерфейсу данные выбранного подопечного с бейджем `«Режим консультанта: просмотр пользователя #12345»`.
4. Возврат в свой личный профиль осуществляется по команде `/me`.
:::
