# 🎨 Стандарт оформления статей и портфолио в VitePress

Этот документ содержит стандарты стилизации и верстки кейсов портфолио для **VitePress**, обеспечивающие максимальную визуальную привлекательность, высокую информационную плотность и аккуратный рендеринг как в светлой, так и в темной теме.

---

## 📌 1. Анатомия идеальной статьи портфолио

Каждая страница кейса должна иметь следующую четкую структуру:

1. **Заголовок H1 с плашками технологий `<Badge>`**
2. **Главный баннер / скриншот проекта**
3. **::: info Карточка проекта** (двухколоночная сводная таблица)
4. **📌 Обзор проекта** (цели, задачи, ссылки на демо)
5. **⭐ Ключевое преимущество / Выполненные работы** (сворачиваемый `::: details`)
6. **⚡ Технические решения и сложности** (`::: tip`, `::: warning`, `::: danger`)
7. **💡 Примеры из практики / ТЗ / Код** (детализированные блоки с диффами)
8. **📈 Итоговые результаты** (сводная таблица достижений)

---

## 🏷️ 2. Плашки `<Badge>`

Используются в заголовках и подзаголовках для быстрого считывания стека и метаданных.

```markdown
# Название Проекта <Badge type="tip" text="WordPress" /> <Badge type="warning" text="PHP 8" /> <Badge type="info" text="JS ES6" />

### 13.1 — Перенести id на heading <Badge type="info" text="index.php" />
### Сложность: Layout Shift <Badge type="danger" text="CLS" />
### Оптимизация производительности <Badge type="danger" text="N+1 → 1" />
```

**Типы плашек:**
- `type="tip"` — стек технологий, основные компоненты (зеленый)
- `type="info"` — имена файлов, модули, статусы (синий)
- `type="warning"` — сроки, временные решения (желтый)
- `type="danger"` — типы проблем, критические метрики (красный)

## 📦 3. Кастомные контейнеры (Custom Containers)

### 📋 `::: info` (Карточка проекта и контекст)
Используется для начального карточки проекта, сводок и контекстной информации.

````markdown
::: info 📋 Карточка проекта

| | |
|---|---|
| **Стек** | WordPress, PHP 8, JavaScript ES6, HTML5/CSS3 |
| **Сроки** | Разработка шаблонов — **2 недели**, обработка контента — **1 неделя** |
| **Роль** | Full-stack Разработчик / Архитектор решений |
| **Масштаб** | 107 рубрик классов API · 1 656 статей методов |
| **Рабочий пример** | 🔗 [example.com/api/](https://example.com) |

:::
````

### 💡 `::: tip` (Решения, UX и этапы)
Используется для демонстрации удачных архитектурных решений, этапов проекта и UX-улучшений.

````markdown
::: tip 💡 Решение: Синхронный Pre-open Hash Script
1. Скрипт отрабатывает мгновенно в процессе HTML-парсинга — **до первого paint**.
2. Считывает `window.location.hash` и раскрывает целевой блок.
3. Браузер совершает скролл сразу к открытому блоку — **0 CLS**.
:::
````

### ⚠️ `::: warning` (Описание проблем и UX-багов)
Используется для подсвечивания выявленных инженерных проблем и сложных кейсов.

````markdown
::: warning Проблема: Cumulative Layout Shift
При переходе по прямой якорной ссылке контент внутри закрытого аккордеона вызывал неприятный **скачок высоты страницы**, сбивая точку фокуса пользователя.
:::
````

### 🚨 `::: danger` (Критические архитектурные узкие места)
Используется для демонстрации тяжелых бэкенд/производительных проблем (например, $N+1$ SQL-запросов, ресурсоемкие алгоритмы).

````markdown
::: danger Проблема: N+1 SQL-запросов
Вызов `WP_Query` внутри цикла для каждого класса генерировал более **201 SQL-запроса** за одну загрузку страницы.
:::
````

### 🔍 `::: details` (Сворачиваемые тяжелые блоки)
Используется для скрытия длинных списков задач, полных ТЗ, больших кусков кода и редких подробностей, чтобы не перегружать основной поток чтения.

````markdown
::: details 📋 Посмотреть полное реальное Техническое Задание (ТЗ № 13)
Текст задания, декомпозиция, требования...
:::
````

## 💻 4. Форматирование кода и диффов

VitePress поддерживает подсветку и маркера диффов напрямую в блоках кода:

### 🔴/🟢 Цветной Diff (Было / Стало)

````markdown
```php
// Было: старый код
<summary id="<?= $accordion_id ?>">  // [!code --]

// Стало: новый оптимизированный код
<span class="r7-api-class__accordion-heading" id="<?= $accordion_id ?>">  // [!code ++]
```
````

### 💛 Подсветка ключевых и проблемных строк

````markdown
```php
foreach ($api_classes as $class_term) {
    $posts = new WP_Query(['cat' => $class_term->term_id]); // [!code warning]
}

// Оптимизированный вызов:
'posts_per_page' => $posts_per_page * count( $term_ids ), // [!code highlight]
'update_post_term_cache' => true, // Прогрев кэша // [!code highlight]
```
````

## 📊 5. Сравнительные таблицы и метрики

Всегда оформлять сравнения «До / После» и итоговые результаты в виде чистых Markdown-таблиц:

````markdown
| Метрика | До | После | Улучшение |
|---|---|---|---|
| SQL-запросы | 201 | 2 | **×100** |
| Время генерации | 1.4 сек | 0.08 сек | **×17.5** |
````

````markdown
::: tip 🏆 Достижения проекта
| Метрика | Результат |
|---|---|
| ⏱️ Скорость обработки | **1 656 статей** стандартизированы за **1 неделю** |

| ⚡ Производительность БД | Нагрузка снижена в **100 раз** (201 → 2 запроса) |
:::
````

## 🚫 6. КРИТИЧЕСКИЕ ПРАВИЛА И ЗАПРЕТЫ (VitePress Gotchas)

### ❌ 1. ЗАПРЕТ вложенных контейнеров `:::`
**Строго запрещено** вкладывать `::: code-group` или любой другой `:::` внутрь `::: details` или `::: tip`.
*Причина:* VitePress парсер считает первый же встреченный `:::` закрытием внешнего контейнера. Это разрывает верстку всей оставшейся страницы!

- ❌ **НЕПРАВИЛЬНО:**
  ```markdown
  ::: details
  ::: code-group
  ...
  :::
  :::
  ```
- ✅ **ПРАВИЛЬНО:** Использовать один стандартный блок кода (с комментариями `/* Desktop */` / `/* Mobile */`) или выносить `code-group` за пределы `details`.

### ❌ 2. Чекбоксы внутри `::: details`
Вложенные task-листы (`- [x]`) внутри `details` могут рендериться как обычный сырой текст.
- ❌ **НЕПРАВИЛЬНО:** `- [x] Сделать задачу`
- ✅ **ПРАВИЛЬНО:** `- ✅ Сделать задачу` или `- 🟢 Сделать задачу`

### ❌ 3. Сырые Mermaid диаграммы
Не вставлять ````mermaid` блоки, если в проекте не установлен `vitepress-plugin-mermaid`.
- ✅ **ПРАВИЛЬНО:** Использовать `::: info 🗺️` или `::: tip` со списком шагов и визуальными стрелками (`➔`).
