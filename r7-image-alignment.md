## <SolarIcon name="pin" /> Project Overview and Requirements

### Problem Description

When editing articles and FAQ entries in the WordPress admin panel for the [R7 Support Center](https://support.r7-office.ru/), content managers regularly selected **“Center”** alignment for uploaded illustrations and screenshots. However, on the frontend all images were displayed without centering, aligned to the left edge.

### Technical Root-Cause Analysis

1. In the `themes/r7/assets/stylesheets/common.css` stylesheet, images inside articles had automatic horizontal margins, but the `display: block` property was commented out:
   ```css
   .faq-item__answer img,
   .wysiwyg-result img {
       /* display: block; */ /* [!code warning] */
       max-width: 100%;
       height: auto;
       margin-right: auto;
       margin-left: auto;
   }
   ```
   Because the `<img>` tag is inline by default, `margin-left: auto` and `margin-right: auto` do not work unless its display type is changed to `block` or `inline-block`.
2. Simply uncommenting `display: block;` for the `.wysiwyg-result img` selector turned every image inside an article—including small inline icons, emoji, and arrows—into a block element, moved it onto a new line, and completely broke the layout.
3. The theme had no proper CSS rules for WordPress’s standard alignment class, `.aligncenter`.

### Task Scope (Requirements)

* **In scope:** Configure correct centering only for images (and their parent containers) explicitly assigned center alignment in the admin panel (the `.aligncenter` class).
* **Safety:** Isolate the rules within `.wysiwyg-result` and `.faq-item__answer` so they do not affect icons, the header, footer, sidebars, or article lists.
* **Out of scope:** Left (`.alignleft`) and right (`.alignright`) alignment—these classes remained unchanged to avoid visual regressions.

## <SolarIcon name="lightbulb" /> Most Complex Task Example: Task 01 — Requirements and Markup Analysis

::: details <SolarIcon name="clipboard" /> View the Full Requirements for Task 01 (WordPress Markup Analysis)

### WordPress Markup Examined (`.aligncenter` Output Variants)

Depending on the editor (Classic Editor / Gutenberg) and whether links or captions are present, WordPress generates the `.aligncenter` class in four distinct markup patterns:

#### 1. Image Without a Link or Caption (Classic Editor)
```html
<img class="aligncenter size-medium wp-image-1234" src="/image.png" alt="Example" />
```

#### 2. Image With a Link (Including Modal-Window Processing in `functions.php`)
The `_convert_image_links_fast` function converts image links into a `<figure>` tag:
```html
<figure class="js-popup-open-link aligncenter size-medium" data-popup="certificate-popup">
    <img class="aligncenter size-medium wp-image-1234" src="/image.png" alt="Example" />
</figure>
```

#### 3. Image With a Caption (Gutenberg / Block Editor)
```html
<figure class="wp-block-image aligncenter size-large">
    <img src="/image.png" alt="Example" />
    <figcaption>Illustration caption</figcaption>
</figure>
```

#### 4. Image With a Caption (Classic Editor)
```html
<div class="wp-caption aligncenter">
    <img class="aligncenter size-medium" src="/image.png" alt="Example" />
    <p class="wp-caption-text">Illustration caption</p>
</div>
```

**Analysis conclusion:** The `.aligncenter` class may appear on the `<img>` itself, on a container (`figure`, `div`), or on both. The CSS solution must cover all 4 scenarios at once.

## <SolarIcon name="bolt" /> Technical Solutions and Key Challenges

### Challenge: Preserving Inline Icon Behavior

::: warning Problem
Setting `img { display: block; margin: auto; }` causes small icons and emoji within article text to move onto new lines, creating a visual break.
:::

::: tip <SolarIcon name="lightbulb" /> Solution: Isolated Cascade
The CSS rules were tied strictly to the presence of `.aligncenter` on the element or its immediate container:

```css
/* ===== Centering images ===== */

/* 1. Center containers (figure, div, p) with the aligncenter class */
.wysiwyg-result .aligncenter,
.faq-item__answer .aligncenter {
    display: block;
    margin-left: auto;
    margin-right: auto;
    text-align: center;
}

/* 2. Center images inside these containers, or when the class is on the img itself */
.wysiwyg-result img.aligncenter,
.wysiwyg-result .aligncenter img,
.faq-item__answer img.aligncenter,
.faq-item__answer .aligncenter img {
    display: block;
    margin-left: auto;
    margin-right: auto;
}

/* 3. Center image captions */
.wysiwyg-result .aligncenter figcaption,
.wysiwyg-result .aligncenter .wp-caption-text,
.faq-item__answer .aligncenter figcaption,
.faq-item__answer .aligncenter .wp-caption-text {
    text-align: center;
    margin-top: calc(12 / 16 * 1rem);
    font-size: calc(14 / 16 * 1rem);
    color: var(--ne-lght-600, #8b929b);
}

/* Accessibility: remove abrupt jumps when reduced motion is enabled */
@media (prefers-reduced-motion: reduce) {
    .wysiwyg-result img.aligncenter,
    .faq-item__answer img.aligncenter {
        transition: none !important;
    }
}
```
